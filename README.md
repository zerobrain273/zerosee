# zerosee

**Reconnaissance веб-инфраструктуры на C++20 для Linux.** TCP-сканирование,
HTTP/HTTPS-наблюдения и отчёты с доказательствами, контекстом и ограничениями.

Версия 0.2.0. Работают две команды:

- `scan` — проверка доступности TCP-портов одного IPv4-хоста.
- `web` — исследование одного URL и разрешённой цепочки перенаправлений.

Это исследовательский инструмент: отсутствие наблюдений не доказывает безопасность,
а заголовок с версией не доказывает наличие CVE. Shodan не подключён.

## Быстрый старт

Зависимости: компилятор C++20, CMake 3.20+, libcurl 7.85+ с TLS-бэкендом,
nlohmann/json 3.10+. Для тестов и лаборатории нужны Python 3 и OpenSSL CLI.
В нашем Arch зависимости уже присутствуют. На Ubuntu нужны пакеты разработки
`libcurl4-openssl-dev` и `nlohmann-json3-dev`, а также инструменты сборки.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j 2
ctest --test-dir build -V
./build/zerosee -h
./build/zerosee web -h
```

Без Python-тестов: добавить `-DBUILD_TESTING=OFF` при конфигурации CMake.
В текущем окружении `~/.local/bin/zerosee` ссылается на `build/zerosee`, поэтому
после сборки команда доступна из любой папки. На другом компьютере можно установить
отдельную копию: `cmake --install build --prefix "$HOME/.local"` и добавить
`~/.local/bin` в PATH. Копию нужно переустанавливать после изменений.

## Демонстрация одной командой

Из папки проекта:

```bash
python3 lab/demo.py
```

Скрипт создаёт временный локальный HTTP/HTTPS-стенд и CA, проверяет четыре сценария
и оставляет JSON/Markdown в `reports/demo/`:

1. HTTP с относительным редиректом и cookies без защитных атрибутов.
2. HTTPS с доверенным лабораторным сертификатом и защитными заголовками.
3. Заблокированный переход за границу origin.
4. Отказ доверять лабораторному сертификату без явно указанной CA.

Серверы работают только на `127.0.0.1`. По окончании серверы останавливаются,
временные ключи удаляются. Для повторного запуска укажите новую папку:

```bash
python3 lab/demo.py --output reports/demo-2
```

Для ручного исследования стенда см. [lab/README.md](lab/README.md).

## TCP-сканирование

```bash
zerosee scan 127.0.0.1 -p 22,80,443,8000-8010 -t 500 -c 4
zerosee scan 127.0.0.1 -p 1-65535 --dry-run
```

| Флаг | Значение |
|---|---|
| `-h`, `--help` | Справка; также `scan -h` и `web -h` |
| `-V`, `--version` | Версия программы |
| `-p`, `--ports` | Список/диапазоны портов 1–65535, без пробелов |
| `-t`, `--timeout-ms` | Таймаут на порт 1–60000 мс, по умолчанию 1000 |
| `-c`, `--concurrency` | 1–256 активных проверок, по умолчанию 16 |
| `--dry-run` | Проверка параметров без подключения |
| `--no-banner` | Скрыть ASCII-баннер ZS2E |

Порты сортируются, повторы удаляются. Вывод появляется после завершения всех проверок.
`-c 1` даёт последовательный режим. Параллельность не равна ограничению запросов в секунду.
Слитные флаги и запись через `=` пока не поддерживаются; адрес стоит перед флагами.

| Результат | Значение |
|---|---|
| OPEN | TCP-соединение установлено |
| REFUSED | Получен отказ подключения |
| TIMEOUT | Истёк срок ожидания; причина не установлена |
| ERROR | Другая ошибка с errno и пояснением |

`scan` не угадывает HTTP по номеру порта. Для исследования найденного веб-сервиса
вызовите `web` с явной схемой, именем хоста и путём.

## HTTP и HTTPS

```bash
zerosee web http://127.0.0.1:8000/redirect
zerosee web https://localhost:8443/strong --connect-ip 127.0.0.1 --ca-file lab/.certs/ca.pem
```

Используется GET. Собираются статус, peer IP, заголовки (с сохранением повторов),
атрибуты cookies, цепочка редиректов, длительность и сведения о сертификатах.
Тело не сохраняется и не анализируется. Cookies не воспроизводятся в запросах,
а значения скрыты в терминале, JSON и Markdown. URL и другие заголовки могут
содержать чувствительные данные; отчёты — не автоматическое обезличивание всего ответа.

### Область проверки

По умолчанию разрешён **только исходный origin: схема + хост + порт**.
Например, `http://localhost:8000` и `https://localhost:8443` — разные origin.
Переход за пределы разрешения записывается в отчёт, но запрос туда не отправляется.
Чтобы явно разрешить дополнительный origin:

```bash
zerosee web http://localhost:8000/upgrade \
  --allow-origin https://localhost:8443 \
  --connect-ip 127.0.0.1 --ca-file lab/.certs/ca.pem
```

`--allow-origin` повторяемый, без путей и query. HTTPS → HTTP блокируется даже при
явно разрешённом HTTP-origin. Ограничение origin — граница URL, а не IP-allowlist.
DNS может вернуть разные IP. `--connect-ip` фиксирует IPv4 исходного hostname
для всех его разрешённых портов, сохраняя Host/SNI и проверку имени из URL.
Другие явно разрешённые hostname разрешаются обычным DNS.

Веб-команда не использует proxy-переменные окружения, netrc и credentials в URL.
Редиректы обрабатываются нашим кодом, а не автоматическим FOLLOWLOCATION libcurl.

### TLS

Всегда включены проверка цепочки доверия и соответствия сертификата имени из URL.
`--ca-file` задаёт CA bundle для частной PKI; глобальное хранилище системы не меняется.
Опции `--insecure` нет. После ошибки проверки сертификата не делается незаметный
повторный запрос без верификации.

Состояния TLS:

- `verified` — запрос прошёл TLS-проверки, даже если позже возникла ошибка HTTP.
- `verification_failed` — libcurl отказал в проверке имени/доверия сертификата.
- `not_established` — соединение TLS не удалось установить/подтвердить.
- `not_applicable` — обычный HTTP.

Поля цепочки сертификатов зависят от TLS-бэкенда libcurl и могут отсутствовать
при ошибке handshake. Проверка отзыва, перебор шифров и полное TLS-аудирование
не реализованы. `verified` не означает, что проверены все свойства сервера.

### Флаги web

| Флаг | Назначение |
|---|---|
| `-t`, `--timeout-ms` | Дедлайн одного запроса 1–60000 мс, по умолчанию 5000 |
| `--max-redirects` | 0–10 переходов после первого запроса, по умолчанию 5 |
| `--allow-origin` | Дополнительный точный origin, до 16 |
| `--connect-ip` | IPv4 для исходного hostname, без изменения Host/SNI |
| `--ca-file` | Локальный CA bundle |
| `--json` | Создать JSON-отчёт |
| `--markdown` | Создать Markdown-отчёт для чтения/Obsidian |
| `--no-banner` | Скрыть баннер |

Лимиты запроса: 64 КиБ заголовков, 200 полей, 64 КиБ тела. Превышение лимита
заголовков — ошибка. Длинное тело намеренно обрывается, отмечается `body_truncated`;
уже полученные полные заголовки можно исследовать. Неполные/ошибочные ответы не
порождают заключения об отсутствующих заголовках. Циклы и неоднозначный Location
останавливают цепочку. Максимальная длительность серии зависит от числа переходов.

## Проверки конфигурации

У каждого вывода есть `id`, `level`, `url`, `evidence`, `context`, `recommendation`.
Уровни `info` и `review` означают сведения и пункты для проверки человеком,
а не автоматически доказанные уязвимости.

- Ошибка проверки TLS: цепочка/имя/сроки/локальная CA требуют проверки.
- HTTP без шифрования: отдельно учитывается возможность редиректа на HTTPS.
- HSTS отсутствует на HTTPS или содержит `max-age=0`.
- Для успешного HTML: не наблюдаются CSP, политика фреймов или `nosniff`.
- Cookie без Secure/HttpOnly/явного корректного SameSite.
- SameSite=None без Secure и нарушения требований `__Host-`/`__Secure-`.
- Server/X-Powered-By как неподтверждённые технологические подсказки.

Не выполняются: эксплуатация, перебор URL, вход в аккаунт, проверка XSS/SQLi,
доказательство CSRF/clickjacking, парсинг CSP целиком, проверка HSTS preload,
сопоставление баннеров с CVE. Назначение cookie нельзя определить по наличию флага.

## Отчёты

```bash
mkdir -p reports
zerosee web http://127.0.0.1:8000/weak \
  --json reports/weak.json --markdown reports/weak.md
```

Отчёты пока относятся к команде `web`. JSON имеет `schema_version: 1`, метаданные,
scope, последовательность `hops`, `findings`, `stop_reason` и `limitations`.
Markdown включает доказательства и рекомендации; HTML/Markdown-разметка из
ответов экранируется, управляющие символы не выполняются в терминале.

Существующие файлы не перезаписываются. Запись идёт во временный файл с правами
0600 в том же каталоге и публикуется атомарно без замены существующего имени.
Два отчёта публикуются независимо: если второй записать не удалось, первый
может уже существовать. Папку назначения необходимо создать заранее.

Коды завершения:

- `0`: scan завершён без ERROR; web получил конечный ответ либо остановился на
  границе scope/запрете downgrade. HTTP 4xx/5xx — полученные ответы, не ошибки транспорта.
- `1`: ошибка выполнения/записи; для web также цикл, лимит переходов или некорректный Location.
- `2`: неправильный ввод.

Наличие `review`-наблюдений само по себе не меняет код завершения.

## Проверки и ограничения среды

```bash
ctest --test-dir build -V
python3 tests/test_web_integration.py ./build/zerosee
```

Офлайн-тесты покрывают CLI, дедлайны и сокеты через имитацию, пул потоков,
нормализацию URL, scope, редиректы, cookie-атрибуты, контекст правил, лимиты,
экранирование отчётов и запрет перезаписи.

Интеграционные тесты автоматически поднимают HTTP/HTTPS на loopback и проверяют
реальный libcurl: доверенную/недоверенную CA, неправильное имя, редиректы, cookies,
лимиты и таймаут. Требуются локальные сокеты. Если среда запрещает их создание,
тесты явно пропускаются. `ZEROSEE_REQUIRE_NETWORK_TESTS=1` запрещает такие пропуски
для CI. Отдельно без сети проверяется лабораторная цепочка и hostname через OpenSSL.

В среде агента сетевые интеграционные проверки недоступны. Пользователь ранее
подтвердил реальную работу TCP OPEN/REFUSED; это не заменяет проверку нового веб-модуля.
